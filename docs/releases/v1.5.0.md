# Ghosted 1.5.0

**Your own agent can run the logbook.** Ghosted now serves an MCP server, pairs with an
agent over a short code instead of a pasted secret, and the board you have open updates
itself while the agent works.

This is the release where Ghosted stops being only a place you type into. The app still
runs no model and holds no API key — the agent is yours, on your machine, with the
credentials you already pay for. What changed is that it can now reach your applications
with exactly the permissions you chose, and nothing more.

## Pair it, don't paste it

Settings → **Agent access** mints a code (`XXXX-XXXX`, ten minutes) and a prompt. Your
agent claims the code, you approve the claim in the app, and the token is handed to the
agent over its own connection — it never passes through a chat log or a screenshot.

Pick a scope when you start: **read only**, **read and edit**, or **full access** with the
destructive tools. The scope decides which tools exist on that connection, so a read-only
agent has nothing to be talked into, and no scope reaches your account: no email, no
password, no session, no deletion. Connected agents are listed with their scope and last
use, and revoking one cuts it off on its next request.

If your client only takes a config file, *Create a token instead* gives you the block.

## What an agent can do

Applications and milestones, nothing else. Read them, file one, retitle a step, mark it
done, add a note — and with full access, archive, delete a step or reset a timeline.

- **An idempotent create for automation.** `find_or_create_application` matches the posting
  URL first (ignoring `http`/`https`, `www.`, a trailing slash, a fragment and tracking
  parameters), then company + role, and reports whether it wrote anything. An email digest
  or an auto-applier can run the same finding twice and update instead of duplicating; the
  lookup and insert share a transaction under a lock, so two runs at once still make one
  row.
- **Duplicates are a question, not a surprise.** Filing a posting that is already on the
  board shows what you have and offers to open it, or to file a second one anyway — and
  the agent's create is held to the same rule, with `force: true` as its second press.
- **The board updates while you watch.** An open dashboard polls a cheap fingerprint every
  15 seconds and refetches when it moved, so the row an agent just filed appears on its own.
- **The agent is given a guide**, not just tool descriptions: which statuses the timeline
  derives, that `displayStatus` is what to report, that a rejection belongs in the comment
  of the step it happened at, and that a known hiring process should be written into the
  timeline rather than left as five defaults.

## Also in this release

- **Appearance is a setting with three answers** — System, Light, Dark — in Settings, with
  System as the default. The night-mode toggle is gone from the user menu.
- **Board or list moved into the user menu**, so the toolbar gets its width back.
- **A security review of the whole agent surface**, with six fixes and the sixteen attacks
  it refused: [docs/reviews/security-review-agent-access-2026-11-01.md](../reviews/security-review-agent-access-2026-11-01.md).
- The landing says MCP shipped rather than "coming soon", the README gained the application
  page next to the board, and the screenshots no longer carry the Next dev badge.

## Updating

Two migrations (`0016`–`0018`) run at container start as usual; nothing new to configure,
no new environment variable. Existing installations keep working with no agent connected —
the feature is inert until you pair something.

## Verifying the agent connection

```bash
curl -s https://<your-host>/ouija \
  -H "Authorization: Bearer ghosted_agt_…" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```
